# Settings: workspace, people, ad accounts, AI usage and integrations

All of this is read from the server. The page only shows what a role may do; the server enforces it on every request.

- **Workspace and people:** name, id, creation time, mode (SIMULATED or LIVE) and your role with what it allows. The people table (admins and owners can read it) lists role and status. Owners who signed in as a person can add someone by user id, change a role or remove them (remove needs a second click). The server prevents removing the last owner. In local-development sign-in (`AUTH_MODE=workspace_token`) there are no user accounts: the page says so, the controls are disabled, and the workspace token acts like an admin that can never manage people. Roles and members need `AUTH_MODE=oidc`.
- **Meta ad accounts:** in mock mode the page says Meta is simulated and no account is needed. In live mode it lists the accounts an owner authorized for this workspace. Live ad creation is not enabled in this release.
- **AI: status, usage and cost:** mode, whether each provider is available and whether a key is present on the server (never the key), the live spending ceiling with spent, held and remaining amounts, and request counts for today and this month split into simulated, local and live. Costs are estimates from token counts and the price list in this app, not the provider's bill. A model with no configured price is counted as unknown cost, not as free.
- **Integrations:** for AI, Meta Ads, GoHighLevel, sign-in and credentials: status (SIMULATED, LIVE, LOCAL, UNAVAILABLE), what it means, what it can do and who may change it, and the last test. Only AI has an explicit connection test. A simulated test verifies nothing and is not recorded as a result. A live AI setup with no successful test is shown as "Configured but NOT verified". Meta and GoHighLevel say they were never tested. A key or setting being present is never shown as proof that something works.

**Integration registry (Phase 8).** Under Integrations, an admin or owner also sees the server-built registry: each adapter's state, exact capabilities, limits, data provenance and failure behaviour, the actions that could ever affect the outside world, declared future channels, simulated self-tests and read-only previews. It describes; it has no switch. See [integrations-readiness.md](integrations-readiness.md).
